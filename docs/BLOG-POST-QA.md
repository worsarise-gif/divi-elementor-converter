# Blog post / core Blog release QA - 1.5.0

Date: October 9, 2026. Scope: ordinary WordPress post targets and a bounded core `et_pb_blog` listing adapter. [Mapping contract](BLOG-POST-MAPPING.md), [user workflow](USER-GUIDE.md).

The supplied individual post export is Divi 4.16 and contains one Text module. It converts to valid native Elementor controls; its actual article markup is compared directly with the source. The official Brokerage Blog preset is Divi 4.8.2. Source fields and selected preset are resolved independently from the existing DiviGear adapter. Customer content and all private test fixtures are excluded from the release ZIP.

QA uses WordPress 7.1.2, Elementor 4.3.3, UAE 2.9.5, PHP 8.3.35, SQLite and MariaDB 11.4.11. Standalone tests also use PHP 8.0.30. Tests cover existing and new post drafts, mixed page/post jobs, exact target kind/ID, saved Apply without duplicate conversion jobs, source categories mapped to destination terms, deleted/wrong-taxonomy categories, bounded published-only queries, offset-aware pagination, Unicode/manual/converted-post excerpts, post metadata/date preservation, clearing jobs and exact rollback. Existing DiviGear, page/UAE, fonts, media, forms, source links and other previous regressions remain part of the acceptance run.

A regression uncovered an unnecessary WordPress post save during rollback, which reset a draft's original date. Rollback now avoids saving unchanged body content; recovery of changed legacy body content uses an explicit edit-date flag. Post status participates in the saved-target fingerprint. Original article body, title, slug, author, date, manual excerpt, categories, tags, thumbnail and SEO are verified during Apply and rollback.

Browser QA checks actual frontend list/masonry, seven viewport widths (320-1440), source title sizes, ordered column placement, card gaps, overflow and independent pagination. The admin test uploads the customer's post export, submits an explicit older-post ID through the real mapping form, waits for completed analysis and applies the saved result through Apply to Post in the same job. Final measured counts and package hashes are recorded in `BLOG-POST-EVIDENCE.json` after acceptance.

Visual review also reproduced a desktop-to-mobile masonry defect: old inline column/row placements created implicit CSS grid tracks after a breakpoint change. The layout now clears old placements before measuring and packing the new grid. Acceptance includes seven viewport transitions without a page reload, in both directions, with column/order/gap/overflow checks. Square featured-image fixtures distinguish Divi's 8:5 crop from an accidental natural-ratio fallback. The ratio and fit remain native editable controls.

Limits: source-rendered screenshots for complete Blog visual parity and the interactive Elementor editor are not accepted here. The previous local editor startup blocked before displaying a usable preview; frontend/native control/template tests must not be described as editor acceptance. Pro/WooCommerce providers, minimum PHP/WordPress runtime versions and live destination themes remain untested. Core full-content/current-archive/CPT/custom-overlay/card-shadow modes retain the original module and block Apply unless an explicitly configured valid template replacement is chosen. Masonry column count/gaps and inherited defaults are documented adaptations when their exact values are absent from the export. Ace Post Grid requires this plugin active. Individual layouts do not import a site's post database or global single-post conditions.
